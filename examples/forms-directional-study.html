Same fields · five directions

The system has no input pattern yet. This study proposes five — each a self-consistent interpretation of the visual language, not a stylistic variant. Every direction renders the same form (a job submission with name, queue, priority, GPU count, runtime, environment, classification) so the directions are comparable on the same problem.

All five obey the foundation: hard edges, no shadows, mono-only, the two-accent hierarchy, surface stepping for elevation, dashed-vs-solid divider semantics. They differ in where the chrome lives — whether the field is a prompt, a row, a panel, a clause, or a cell — and that choice carries voice.

End matter: a recommendation table mapping direction → use case, plus the one direction we'd ship as the default.

[01] CLI Prompt prompt · bottom-rule · cursor

Every field is a terminal prompt. A teal › glyph, a lowercase label, a writable line. No surface fill, no field perimeter — only a 1px bottom rule that brightens to teal on focus, with a blinking caret to advertise the active line. This is the most literal read of "terminal-derived." It earns its keep on single-task forms where the operator already knows the field set; it punishes wide forms because there's nothing to anchor the eye between rows.

Strengths
  • Maximum signal density — almost no chrome.
  • Native-feeling for power users; reads like a real CLI.
  • Caret animation makes "you are here" unmistakable.
Weaknesses
  • No perimeter cues — long forms become hard to scan.
  • Group affordances (sections, repeats) require extra invention.
  • Less forgiving for new users who haven't internalized the field set.
[02] Spec Sheet 2-col · recessed-label · dashed-row

The form is a property table: each row a label cell on --color-bg and a value cell on --color-surface-1, dashed between rows because they're parts of the same artifact. The label column is fixed-width and uppercase; the value column is the input. This is the closest direction to the system's stated voice — "spec sheet, system console." It scales to dozens of fields without losing structure.

[03] Console Frame paneled · corner-spec · instrument-cluster

Each field becomes its own panel: solid border, a head row holding the label and a small uppercase corner spec (the same convention the style tile's metric cells use), a dashed rule, then the input on the recessed bg. Fields tile into a 2-column grid like an instrument cluster. Maximum chrome per field. Best for sparse, high-stakes forms — credentials, deployment configs — where each field deserves to look weighty.

Strengths
  • Each field reads as instrument-grade; fits high-stakes contexts.
  • Corner spec carries type/constraint info without inventing tooltips.
  • Tiles naturally — short fields pair into rows, long fields span.
Weaknesses
  • Per-field overhead is heavy — wasteful for forms over ~10 fields.
  • Visual rhythm is busy at any density above standard.
  • Dashed/solid rules already mean things; here they multiply.
[04] Brand Spine 2px-spine · focused-only · clause-pattern

Each field rests quietly on --color-bg; the active field grows a 2px teal left spine — the same 2px spine that policy cards use to mark a structured clause. The rule is metaphor: filling out a field is authoring a clause. Subtle perimeter at rest, brand-present at focus. Closer in voice to the policy-authoring side of the product than to the operator side.

⌘⏎ submit
Strengths
  • Quietest at rest of the five — least visual noise.
  • Re-uses the policy-card spine, so the language is already in the system.
  • Pairs naturally with policy/governance flows.
Weaknesses
  • Spine carries focus state; you lose it as a structural-section signal in the same context.
  • Wide / multi-pane layouts feel underdrawn — lacks the perimeter Spec Sheet has.
  • Less obvious as "form" at first glance; closer to a doc editor.
[05] Field Tape horizontal · vertical-rules · status-bar-kin

Fields collapse into a horizontal strip — vertical rules between cells, label above value inside each cell, like a writable status bar. This is not a replacement for a full form — it's the pattern for the toolbar/filter strip that sits above a result list, the docked submit-bar at the bottom of a page, or a compact deploy form when the screen is mostly something else. Adjacent cells let related fields share a row at very high density.

Strengths
  • Highest information density per vertical pixel.
  • Natural fit alongside dense tables — pairs with the result list it filters.
  • Reads as kin to the existing status-bar pattern; voice-consistent.
Weaknesses
  • Doesn't scale past ~7 short fields — overflow is awkward.
  • Long-text inputs (textarea) need a second row, breaking the tape.
  • Labels run very small; gets cramped on narrow viewports.
[06] Recommendation direction → use-case

Default the system to direction [02] Spec Sheet — it reads truest to the stated voice, scales to any field count, and is the friendliest to extend with grouped sections, repeats, and conditional rows. The other four are not alternates to choose between; they are specialized patterns with sharper edges. Reach for them when the context calls.

Direction Reach for it when… Avoid when… Status
[01] CLI PromptThe terminal-derived voice cranked all the way up. Operator power-tools, single-task forms, "submit a job" pages where the user already knows the schema. New users; long forms (>10 fields); multi-section configs needing strong group cues. specialized
[02] Spec SheetForm as property table; closest to "spec sheet" voice. Default. Configuration screens, settings, anything with ≥5 fields. Always a safe choice. Narrow viewports (label column too greedy under ~720px). default
[03] Console FramePer-field panels, instrument-cluster layout. Sparse, high-stakes forms — credentials, deploy configs, anything with strict per-field constraints worth advertising. Forms over ~10 fields; mobile/compact density (chrome eats the screen). specialized
[04] Brand SpineQuiet at rest, focused field grows the policy-card spine. Policy authoring, governance/compliance flows — anywhere the form authors something that becomes a clause. Operator-side surfaces where you want strong "this is a form, not a doc" affordance. specialized
[05] Field TapeHorizontal strip of inline cells. Filter/query bars, docked submit-bars, compact deploy forms, anywhere the form is supporting the page rather than being it. Standalone form pages; any form needing ≥7 short fields or multiple long-text fields. specialized
