sovereign_terminal

BASE RUNTIME
INK AQUA · TEAL
MODE DARK
REV 0.1

This is the visual reference for every Amalgamy LaunchHPC prototype. The system is dark, monospace-led, terminal-derived. Hard edges, no shadows; surfaces step in discrete depths; brand presence is carried by a two-color hierarchy of aqua and teal. Use this page to find a token, copy a hex, or look up the canonical shape of a component. For the rules and the why, see visual-language.md; for Claude Code skills, see the foundation SKILL.md and component skills.

[01] Overview 5 stances · 1 voice

Five stances hold across every Amalgamy prototype. They're stated as constraints because each one cuts off a large family of decisions that would otherwise need to be re-debated on every screen.

Five Stances SOV_TERM · REV 0.1
01Hard edges, never soft. No border-radius. No box-shadow for elevation. No gradients. Surfaces stack via discrete steps and 1px borders. 02Monospace as voice. JetBrains Mono everywhere. Inter only for executive narrative prose (role-narrative). Never on the same line. 03Stepped surfaces. Four depths from --color-bg to --color-surface-3. Movement up the stack is one step plus a 1px border — never a shadow. 04Two accents, one hierarchy. Aqua = the single primary CTA on a screen. Teal = everything else brand-present. Teal-deep = structurally important text. Not interchangeable. 05Density and atmosphere are global. One density per prototype. One atmosphere per prototype. They're product modes, not theming gimmicks.

[09] Live Log — Scheduler Decision tail -f · structured · signature

The strongest signature pattern in the system. Recessed header on --color-bg with square traffic-light dots (live = green, glowing). Body uses a 3-column grid: timestamp · level · message. Levels carry the status color vocabulary. Inline code wraps every system value.

[10] Navigation tabs · breadcrumb · sub-nav

Four patterns, one family: tabs for sibling views, breadcrumb for hierarchy (status-bar resident), sidebar for full app shells, sub-nav (chips or segmented) for filtering inside a section. Most prototypes use exactly one of the first three. Sub-nav layers on top.

sub-nav chips · for filtering a list · count inline chip variant
sub-nav segmented · for mutually-exclusive view modes see navigation-patterns.html for full set
[11] Rendering Invariants do these by default

Every component on this system follows these rules unless overridden for a deliberate reason.

Rendering Defaults RULE_INV · ALWAYS
01Imports tokens/amalgamy-reset.css at the top, or inlines its full contents. 02Uses role utility classes for type. <div class="role-metric-display">97.4%</div> over re-stating five primitives. 03Uses CSS variables for all color and border values, never hex codes. 04Hard-edged corners — border-radius: 0. The system has no radius tokens; that is intentional. 05No drop shadows. Elevation is stepping plus a 1px border. Only exception: the inset highlight on primary buttons. 06Tabular numerals on every metric, count, and timestamp. role-metric-display and role-metric-value bake this in. 07Spec annotation in the corner of significant panels. The "this is a spec sheet, not a marketing page" voice.
